Nom de l'app: MaMétéo

En une phrase, elle sert à : Donner en un coup d'œil la météo des lieux où l'utilisateur se rend habituellement, sans qu'il ait à chercher lui-même.
l'application doit afficher les lieux enregistrés sous forme de cartes, Permettre de rechercher ou filtrer un lieu, Lorsqu'on sélectionne un lieu, afficher sa météo complète, Indiquer automatiquement quel est le prochain lieu selon l'heure de passage habituelle, Afficher température, vent, couverture nuageuse, etc.

À qui (prénom + âge + situation) : Jean, 22 ans, serveur dans un restaurant à Baulmes, qui se rend tous les jours à Yverdon après le travail pour retrouver des amis.

L'application doit identifier le prochain lieux en ce référent aux heures de passage habituel, pour l'afficher en tant que lieux principal. L'application doit aussi être capable d'afficher la température, les conditions venteuses et la couverture nuageuse des lieux demander.

Les données (inventées) ressemblent à : fiches de lieux habituels — chacune avec un nom de lieu, une heure de passage habituelle, et les données météo associées (température, vent, couverture nuageuse).

Pourquoi ce n'est pas trop grand pour 4 semaines de code : L'appli repose sur une seule API météo publique et un nombre limité d'écrans (liste des lieux, ajout d'un lieu, détail météo). Pas de compte utilisateur complexe ni de base de données lourde — juste un stockage local des lieux enregistrés et un appel API par consultation.
